# Вспомогательные утилиты

## `migrate_to_imap.py`

Загружает локальные файлы `.eml` в IMAP-ящик. Использует только стандартную
библиотеку Python и отправляет исходные байты файла через `APPEND`, не
пересобирая письмо (пересборка меняет переводы строк, порядок заголовков и
границы MIME).

Типичный сценарий: `mexporter` выгружает почту в `.eml`, затем этот скрипт
заливает её на новый сервер.

### Требования

- Python 3
- Доступ к IMAP-серверу (SSL или обычное соединение)
- Действующие учётные данные ящика

### Порядок работы

1. Экспортируйте письма `mexporter` в каталог, например `mail-export`.
2. Запустите скрипт с конфигом или аргументами (см. ниже).
3. При обрыве просто запустите ту же команду снова: уже загруженные письма
   пропускаются по журналу.

### Конфигурация

Параметры задаются JSON-файлом, аргументами командной строки или обоими
способами; аргументы CLI перекрывают значения конфига.

Из конфига читаются только пять ключей:

```json
{
  "server": "imap.example.com",
  "port": 993,
  "login": "user@example.com",
  "password": "<password>",
  "eml_folder": "C:\\path\\to\\exported-mail"
}
```

`--mailbox`, `--state`, `--log`, `--timeout` и `--ssl`/`--no-ssl` задаются
только аргументами. Не храните настоящие учётные данные в файлах под
контролем версий.

### Использование

Из каталога `scripts`:

```powershell
# С файлом конфигурации
python migrate_to_imap.py --config config.json

# Аргументами командной строки
python migrate_to_imap.py --server imap.example.com --port 993 --login user@example.com --password "<password>" --folder "C:\path\to\exported-mail"

# В отдельную папку IMAP, с явными журналом и логом
python migrate_to_imap.py --config config.json --mailbox "Archive/2025" --state upload.jsonl --log upload.log
```

### Аргументы

| Аргумент | По умолчанию | Описание |
| --- | --- | --- |
| `--config` | — | Путь к JSON-файлу конфигурации |
| `--server` | `imap.example.com` | Имя хоста IMAP-сервера (заглушка: укажите реальный) |
| `--port` | `993` | Порт IMAP (`993` для SSL, `143` для обычного соединения) |
| `--login` | из конфига | Логин и имя пользователя ящика |
| `--password` | из конфига | Пароль ящика |
| `--folder` | текущий каталог | Локальный каталог с `.eml` (сканируется рекурсивно) |
| `--mailbox` | `INBOX` | Целевая папка IMAP-ящика |
| `--state` | `imap_upload_state.jsonl` | Журнал загруженных писем (JSONL) |
| `--timeout` | `60` | Таймаут IMAP-операций в секундах |
| `--log` | `imap_migration.log` | Диагностический лог с таймстампами |
| `-v`, `--verbose` | выключено | Дублировать диагностику в консоль |
| `--ssl` | выключен | Включить SSL/TLS (обязательно для порта `993`) |
| `--no-ssl` | — | Принудительно незашифрованное соединение (порт `143`) |

`--folder` — локальный путь; `--mailbox` — папка на сервере. Это разные вещи,
не перепутайте.

SSL по умолчанию выключен, даже для порта `993`: для защищённого соединения
передайте `--ssl`. Порт `143` и так работает без шифрования.

### Имена журнала и лога

К именам по умолчанию добавляется суффикс
`_<server>_<login>_<mailbox>_<8 hex>` (хеш sha256 от контекста), например
`imap_migration_imap.spaceweb.ru_user@example.com_INBOX_0b375474.log`. Так
параллельные запуски для разных ящиков не смешивают журналы, а после замены
недопустимых символов разные контексты не сливаются в одно имя.

Части суффикса безопасны для Windows: недопустимые символы (`<>:"/\|?*`),
управляющие символы и DEL заменяются/удаляются, зарезервированные имена
(`CON`, `NUL`, `COM1`…) получают префикс `_`, длина каждой части ограничена
40 символами. Явно указанные `--log` и `--state` используются как есть, без
суффикса.

### Поведение

- Рекурсивно находит `*.eml`, сортирует пути и обрабатывает по одному.
- Для каждого файла читает заголовки (для лога) и делает `APPEND` исходных
  байтов с флагом `\Seen`.
- Ключ журнала: `server|login|mailbox|относительный путь|размер файла`.
  Запись пишется и сбрасывается на диск сразу после успешного `APPEND`.
- При обрыве соединения (`timeout`, `abort`) выполняет одно переподключение;
  если оно не удалось — останавливается, журнал остаётся валидным.
- Ошибки разбора и загрузки считаются и не прерывают проход.
- `Ctrl+C` безопасен: журнал сохранён, повторный запуск продолжит с места.
- Между письмами пауза 0,1 с, чтобы не перегружать сервер.

### Коды выхода

| Код | Значение |
| --- | --- |
| `0` | Проход завершён (в том числе с отдельными ошибками) или файлов не найдено |
| `1` | Нет логина, не найден конфиг, не удалось подключиться или авторизоваться |

Отдельные неудачные письма не меняют код выхода — сверяйте итоговый отчёт и
журнал.

### Ограничения

- Сервер не проверяется на дубликаты: идентичность письма — локальный путь и
  размер файла. Переименование или перемещение `.eml` приведёт к повторной
  загрузке.
- Все письма загружаются в одну целевую папку (`--mailbox`); иерархия папок
  экспорта не переносится.
- Дата письма при `APPEND` не передаётся (используется текущее время сервера).

## `package-release.ps1`

Собирает релизные архивы для GitHub Releases: кросс-компиляция
`windows/amd64` и `linux/amd64` с `CGO_ENABLED=0`, затем упаковка в
`dist/mexporter-<version>-windows-x64.zip` и
`dist/mexporter-<version>-linux-x64.tar.gz`. В архив кладутся бинарник,
`README.md`, готовый `mexporter.json` (из `mexporter.example.json`) и пустые
каталоги `session/` и `mail-export/`.

```powershell
.\scripts\package-release.ps1              # версия из git describe
.\scripts\package-release.ps1 -Version v1.2.3
```

## `run_mexporter.ps1` (в корне проекта)

Собирает `go/mexporter.exe`, если его нет, и запускает с переданными
аргументами, возвращая код выхода программы.
